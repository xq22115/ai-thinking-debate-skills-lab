# Changelog — AI Efficiency Operating System

## 0.2.0-rc1 — 2026-08-28

Major evolution from the thin v0.1 orchestration index into an executable efficiency operating contract.

### Added

- 29 machine-readable orchestration modules across intent, context, reasoning, multi-agent, execution, performance, verification, evolution and output.
- Explicit task contract with correction/supersession semantics.
- E0–E6 evidence ladder.
- Capability truth state machine: DISCOVERED → FETCHED → CONFIGURED → INSTALLED → LOADABLE → INVOKABLE → VERIFIED.
- Progressive-disclosure context policy, lean instruction deduplication and claim-preserving compaction.
- Adaptive research/debate stopping based on model delta and marginal information gain.
- Adaptive agent coalition plus selective disagreement routing.
- Strict proof gate for claims of real independent agents.
- Short-critical-section locking, event journal, idempotency, fencing and safe resume.
- Background/non-disruptive desktop execution policy.
- Conversation-bridge vs capability-bridge distinction.
- Hot-path amplification, retry/cache/backpressure controls.
- Completion state machine through HEALTHY.
- Baseline → failure attribution → holdout → promote/rollback skill evolution.
- `runtime-state.schema.json`.
- `SOURCE-MATRIX.md`.
- 31-case `EVALS.md`.

### Strengthened

- `不卡頓 != 秒回`: deep reasoning, model generation, UI publish/render, history materialization and tool/network latency are separate budgets.
- No-goal-shrink: performance work may not disable required features, concurrency, depth or quality.
- Cross-chat convergence: summaries are indexes; exact live repository/runtime evidence owns mutable truth.
- Completion: repository writes, CI PASS, transport success and agent prose cannot substitute for owning-runtime read-back.

### Provenance expansion

Recovered additional prior-account conversation clusters from 2026-08-20 through 2026-08-28, including capability bridging, deep-thinking vs fake waiting, quality evolution/coverage frontier, background non-interference, output stutter vs reasoning depth, primary-task control, durable queue/resume/idempotency, demand-loaded tools/context and owner/supersession/read-back rules.

Mechanisms were also calibrated against current OpenAI/Anthropic guidance and 2026 agent/context research.

### Truth boundary

- One canonical package remains: `ai-efficiency-operating-system`.
- Existing portable core skills remain dependencies; no aliases were created.
- `HOST_LIVE` is not claimed without target-host execution.
- Ten independent review workstreams are not labeled ten real runtime agents unless independent session receipts exist.
