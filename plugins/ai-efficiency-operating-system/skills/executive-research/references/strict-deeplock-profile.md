# STRICT_DEEPLOCK profile

This is an **explicit acceptance profile**, not the default definition of deep thinking.

Use only when the user explicitly requires the historic DeepLock-style thresholds and the host exposes the telemetry needed to verify them.

## Authority planes

Keep separate:

- control plane — frozen contract/state/manifest/evidence ledger/final status;
- cognitive plane — research workers, cross-examiners, gap research, synthesis;
- verification plane — reachability/provenance clustering/read-only audit/deterministic validator/lifecycle gates.

The cognitive plane may propose. It cannot grant completion.

## Worker identity

A strict claim of ten agents requires ten distinct runtime/process/thread identities with start and terminal receipts. Ten roles in one response do not satisfy this. Shared model family remains a correlation risk and must not be described as statistical independence.

Prefer isolated first pass, then bounded cross-examination with fresh search against disputed claims. Preserve minority objections.

## Strict time gate

Required by this profile:

- productive host active elapsed >= 600 s;
- aggregate measured worker execution >= 600 s.

No sleeping, slow streaming or idle padding counts. If productive work ends before the strict gate and no additional meaningful gap research exists, the strict run fails rather than idling into compliance.

Private hidden reasoning duration is not claimed or inferred.

## Strict evidence gate

Required by this profile:

- >= 50 qualified evidence families;
- >= 10 independent domains;
- >= 4 research passes: broad, gap expansion, adversarial, cross-validation;
- critical claims adequately supported across independent families/domains;
- source reachability/provenance audit;
- no unresolved critical contradiction;
- no erased minority objection.

Canonicalize URLs, collapse tracking/format variants, prefer DOI/arXiv identity and union declared common origins. Raw links do not equal independent evidence.

These numeric thresholds are contractual workload floors for this profile. They do **not** override the adaptive research rule that source count alone is not quality.

## Terminal status

If the host cannot prove required time/worker telemetry, maximum status is `PROCESS_COMPLETE`, never `STRICT_COMPLETE`.

Other terminal states include `INCOMPLETE_EVIDENCE`, `BLOCKED`, and `FAILED_VALIDATION`.

A natural-language answer cannot override the validator state.
