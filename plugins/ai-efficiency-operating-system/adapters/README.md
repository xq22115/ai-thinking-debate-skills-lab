# Host Adapters

The AI Efficiency Operating System keeps one canonical goal/evidence/recovery contract and adapts execution to each host rather than pretending every agent runtime has the same tool, session, skill, or verification semantics.

| Host | Adapter | Status | Notes |
|---|---|---|---|
| ChatGPT/Codex | `chatgpt/` | packaged; HOST_LIVE requires owning-surface proof | runtime probes and hosted 10-way checks |
| OpenClaw | `openclaw/` | package candidate; source-locked; HOST_LIVE unverified | native skills, adaptive sub-agents, Workshop learning, bundled Lobster workflows, optional lab Swarm, additive installer |

## Adapter invariant

A host adapter may change execution mechanics, but it may not weaken the root goal, protected capabilities, acceptance tests, completion evidence standard, correction invalidation, or recovery rules.

For OpenClaw, uncertain work belongs to adaptive agent lanes, known repeatable action paths can be compiled into Lobster workflows, and completion still belongs to fresh owning-state evidence.

`PACKAGE != HOST_LIVE` remains true for every adapter.
