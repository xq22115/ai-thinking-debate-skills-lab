# Agent Reliability Research

## Purpose
Investigate the earliest reliability layer that can explain the failure. Keep goal fidelity, context/state, tools/authority, memory, replay, multi-agent handoff, observability, resource lifecycle and evaluation as distinct routes instead of one giant prompt.

## Activate when
Use when reliability mechanisms, long tasks, cross-session continuity, state races, drift, false completion, tool exposure, review authority or runtime lifecycle can change the engineering decision.

## Do not activate
Do not load for ordinary coding, simple factual lookup or a single deterministic edit. Do not load every reliability route by default.

## Antigravity-native execution
Resolve the active workspace, project rules, discovered skills, visible tools/MCP surfaces and runtime permissions first. Load only the smallest route whose discriminator can change the decision. Store bulky evidence in project artifacts rather than the active prompt.

## Workflow
1. Freeze goal/revision and acceptance tests.
2. Classify the failure layer and competing mechanisms.
3. Choose one discriminating probe per live hypothesis.
4. Separate control state, evidence state and runtime state.
5. Repair the earliest causal owner; preserve a failing case.
6. Re-run task, lifecycle and completion regressions.

## Validation
A reliability claim needs exact target/version, a falsifiable case and task-relevant read-back. Re-check after context, workspace, permission, skill or runtime epochs change.

## Boundaries
Research and skills do not create permissions, durable workers or hidden observability. Missing telemetry is `UNKNOWN`, not proof of absence.
