# Plan Arbiter

## Purpose
Choose the route most likely to reach the frozen acceptance state, not the route easiest to describe.

## Activate when
Use for materially different architectures, repair strategies, migration paths, risky sequencing or reversible-vs-irreversible choices.

## Do not activate
Do not generate cosmetic alternatives when only one causal route is plausible or when a factual unknown should be researched first.

## Antigravity-native execution
For each route record mechanism, prerequisites, workspace/runtime capability, acceptance coverage, high-impact assumptions, blast radius, reversibility, cheapest discriminator and rollback. Resolve target identity errors before downstream planning.

## Workflow
1. Generate only causally distinct options.
2. Eliminate routes that violate hard constraints.
3. Probe cheap assumptions that can falsify whole branches.
4. Prefer shared upstream fixes and reversible probes.
5. Select a route with explicit acceptance mapping.
6. Hand effectful execution back to the active goal owner.

## Validation
Return selected route, rejected alternatives, first discriminator, rollback boundary and unresolved uncertainty. A plan is not implementation proof.

## Boundaries
Do not silently downgrade required functionality for convenience. Planning cannot substitute for current evidence when version/runtime facts are load-bearing.
